The protected API page has two tabs: **Keys** and **Quota**.

## Keys

The key table shows a key's name, creation time, and revoke action. It never returns or displays an
existing key's secret. If the account has no keys, the page shows a dedicated empty state and a
**New API Key** action.

Creating a key asks for a clear, unique name such as `Mobile app`. The generated secret then opens
in a dedicated **Shown once** sheet, masked by default. Copy it directly or reveal it temporarily,
save it in a trusted server-side secret manager, and confirm **I've saved it**. After that sheet is
closed, the original secret cannot be recovered; create a replacement key if it was not saved.

UniFi stores only the key's one-way hash for verification and revocation. Deleting a key requires a
confirmation step and warns that every app using it will immediately lose API access.

<Warning>
Treat the generated key as a server-side secret. Do not commit it, expose it in browser code, place
it in screenshots and support messages, or expect UniFi support to recover it later.
</Warning>

API key creation and deletion use the signed-in session and do not require an additional
authenticator OTP. The current Free plan also displays its key-count limit in the Keys view.

## Quota

Quota shows:

- the current plan and active state;
- consumed and available API credits;
- image-credit usage where applicable;
- the current billing cycle;
- the next renewal time;
- an Upgrade link to API Plans.

The page distinguishes API access management from payment authentication: an API key authorizes an
integration, while the web JWT authorizes the signed-in user session.
