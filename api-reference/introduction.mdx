The UniFi API lets a backend authenticate users, inspect supported wallet balances, create
stablecoin payments, and follow each payment through settlement.

This reference is deliberately limited to operations available through the public UniFi developer
kit. Administrative, worker, dashboard, support, scheduling, and agent-orchestration routes are not
part of the public contract.

## Base URL

```text
https://unifi-api-4a5e.onrender.com
```

All requests use HTTPS and JSON unless an endpoint states otherwise.

## Authentication

Most operations require a bearer credential:

```http
Authorization: Bearer <credential>
```

Use a server-side API key for backend integrations or a user JWT returned by the signed-wallet
challenge flow. The liveness check and the two wallet-challenge operations are public.

<Warning>
Never expose an API key in browser code, a mobile application, a public repository, logs, or
analytics events.
</Warning>

## Response envelope

Successful data responses use a consistent envelope:

```json
{
  "status": "200 OK",
  "data": {}
}
```

Operations that do not return a resource use `message` instead of `data`. Error responses are
currently plain text, so application logic should branch on the HTTP status rather than parsing the
message.

## Payment scope

The public developer kit currently exposes payment creation for UniFi-managed wallets. The API
returns a receipt ID immediately; use the receipt endpoint to track the payment from `Processing`
through `Confirmed` and `Finalized`.

Non-custodial signing, bulk-payment orchestration, and internal payment-session operations are not
included in this public reference yet.
