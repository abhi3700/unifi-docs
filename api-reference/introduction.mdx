The UniFi API exposes the payment lifecycle used by the web app and developer tools. The public reference below is intentionally limited to integration-facing routes; internal administration and worker routes are not part of this contract.

## Base URLs

| Environment | URL |
| --- | --- |
| Hosted | `https://unifi-api-4a5e.onrender.com` |
| Local | `http://127.0.0.1:3333` |

## Typical integration

<Steps>
  <Step title="Authenticate">
    Use a server API key, or complete the wallet challenge flow to obtain a JWT.
  </Step>
  <Step title="Read the balance">
    Fetch the spendable balance for the exact user, chain, and stablecoin.
  </Step>
  <Step title="Preflight">
    For a wallet-signed payment, POST the intended payment to the non-custodial preflight endpoint. It returns balance, estimated fee, and Permit2 allowance state.
  </Step>
  <Step title="Create signing data">
    Send the payment base fields—including the preflight fee and a 15-minute deadline—to the Permit2 signing-data endpoint.
  </Step>
  <Step title="Sign and submit">
    Ask the wallet to sign the returned EIP-712 data, then submit the original base fields, nonce, signature, and memo. Store the returned receipt ID.
  </Step>
  <Step title="Reconcile">
    Fetch the receipt until it reaches a state accepted by your product.
  </Step>
</Steps>

## Response envelope

Successful endpoint responses use a JSON envelope:

```json
{
  "status": "200 OK",
  "data": {}
}
```

Some responses add endpoint-specific fields, such as `server_uptime`. Errors currently return a safe plain-text message with the relevant HTTP status.

<Warning>
Use decimal strings for token amounts and fee values. JavaScript floating-point numbers can silently change stablecoin amounts.
</Warning>
